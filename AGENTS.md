# Consignes de développement Berceau communautaire

Ces règles s’appliquent à tout le dépôt dès la phase H et pour toutes les phases suivantes.

- Rédiger tous les nouveaux commentaires et toute la documentation en français, avec un vocabulaire technique précis et compréhensible.
- Pour chaque modification, expliquer les fonctions importantes, les traitements complexes, les conditions particulières, les décisions techniques et les interactions entre modules lorsque cela aide à comprendre le code.
- Éviter les commentaires qui répètent une instruction, les duplications et les modifications inutiles du code existant uniquement pour ajouter des commentaires.
- Choisir des noms de variables et de fonctions explicites ; préserver une organisation lisible.
- Documenter le rôle des nouveaux fichiers importants et leurs dépendances. Maintenir le README à jour pour l’architecture, les modules, le lancement, les limites du prototype et la contribution.
- À la création ou modification du manifeste d’images, documenter sa structure réelle, les conventions de nommage et la procédure complète d’ajout d’une illustration, avec un exemple valide et les modules consommateurs.
- Identifier clairement les fonctionnalités de démonstration et les points d’évolution vers un backend. Ne pas présenter une simulation, une certification locale ou le stockage dans le navigateur comme un service réel.
- Ajouter un commentaire TODO uniquement pour une fonctionnalité restant réellement à développer ; préciser ce qui manque.
- Limiter les changements au besoin traité et préserver les modifications existantes de l’utilisateur. Ne pas modifier les sauvegardes pour les aligner sur le code courant.
- Effectuer les vérifications adaptées au changement et indiquer les résultats ainsi que les limites restantes.
